# 从零制作你的小鲸鱼桌宠

让一张喜欢的角色图，变成会陪你工作的桌面伙伴 AuA。

本指南整理于 2026-09-25，以目前发布的 WhalePet 0.15.1 代码为依据。面向 Windows x64 用户；其他系统没有在本项目中验证。它教你复用现有程序制作自己的角色，不是从空文件开始重写 Electron。

先记住：**先做对一张静态图，再做齐姿势，最后添加动作。每一步都保留原图和可退回的版本。**

## 0. 选择你的路线

| 你想做什么 | 路线 | 需要什么 |
| --- | --- | --- |
| 在自己电脑上换成自己的角色 | A：使用现成桌宠导入图片 | 分享版程序、透明角色图；不用编程 |
| 做一套完整角色并发给朋友 | B：修改源码中的默认素材再打包 | 路线 A 的制作步骤，加 Git、Node.js、PowerShell |
| 了解我们如何走到这一步 | 阅读 [制作记录索引](CREATION_INDEX.md) | 无需安装工具 |

两条路线都要完成第 2–5 步的角色与透明度检查。路线 A 的导入设置仅在本机生效，**不会自动写进发布 ZIP**；要让朋友默认看到你的角色，请完成路线 B。

你可以先只制作「待机、思考、完成」三张，验证成功后再补齐 12 个状态；未替换的状态仍会显示原角色，不能算作已完成的整套作品。

## 1. 先让原版正常运行

### 路线 A：安装现成版本

1. 打开 [WhalePet Releases](https://github.com/552528583benson-cmyk/Whalepet_V1.0/releases/latest)。
2. 下载名字以 `WhalePet-Friends-` 开头的 ZIP，而非自动生成的 Source code ZIP。
3. 完整解压，退出正在运行的旧版，双击「安装 WhalePet.exe」。
4. 从桌面 WhalePet 图标启动，试试单击、拖动与右键「小鲸的控制室」。
5. 记录默认大小和正常拖放的感觉；先确认原版能运行，再换素材。

安装版自带运行环境。不需要为了运行桌宠安装 Python、抠图模型或购买 API。

### 路线 B：建立自己的源码副本

准备 Windows x64、Git、Node.js 22.12 或以上版本以及 npm。使用支持该依赖的 Node 版本，在 PowerShell 中运行：

```powershell
git clone https://github.com/552528583benson-cmyk/Whalepet_V1.0.git MyWhalePet
cd MyWhalePet
npm ci
npm run check
npm start
```

第一次 `npm ci` 需要联网下载依赖与 Electron。运行前退出安装版，避免两个实例争用同一个本机状态桥。命令失败时先解决报错，不要连续执行后面的步骤。

关闭测试窗口后建立自己的分支：

```powershell
git switch -c my-character
```

保留原始下载包。未纳入 Git 的原始绘画另做备份；Git 不会自动保护未提交或被忽略的文件。

**本步完成标志：**不换任何图时，原版能启动、拖动、松手和打开设置。

## 2. 先确定一张角色母版

角色母版就是后续每个姿势都要参照的那一张图。可以自己画、委托绘制，或使用支持参考图的图像生成工具；图像生成服务的费用与条款另计，不等于本地抠图或桌宠本身收费。

在开始生成更多姿势之前，写一张设计卡：

| 项目 | 你的决定 |
| --- | --- |
| 名称与气质 | 例如：有点呆、亲切、活泼，而不是每张都换一种性格 |
| 固定特征 | 发色、眼睛、饰品轮廓、衣服、尾巴形状 |
| 身体比例 | 头身比、裙摆位置、短腿与鞋子要露出多少 |
| 画法 | 描边粗细、阴影颜色、眼睛高光、细节密度 |
| 动作道具 | 书、文件夹或工具；尺寸不能遮掉整个身体 |
| 不能改变的细节 | 例如完整的发箍、连续的呆毛、唯一的一条尾巴 |

先选择完整全身、无遮挡、轮廓清楚的待机图。人物周围留边，脚和尾巴不能贴着画布裁断。缩到实际桌宠大小再判断是否好看，而不只看大图。

不要把「画得更精致」当成「更适合桌宠」：太多细线在小尺寸下会挤在一起。我们最终保留了短而可见的腿、清楚的轮廓，以及略带笨拙感的表情。

**本步完成标志：**你愿意让所有姿势都长得像这张图，并且已经保存未裁切的母版。

## 3. 逐张制作姿势，而不是一次塞满动作大图

每次使用同一母版作为参照，只改变正在做的事、必要的手臂动作和表情。逐张审核比发现整张动作表都有问题后再拆分修补更容易。

当前程序包含以下 12 个状态。右侧名称是路线 B 的默认 PNG 文件名，不是随意起名：

| 状态键 | 含义与动作建议 | 文件名 |
| --- | --- | --- |
| `idle` | 待机：放松站立 | `idle.png` |
| `connecting` | 连接：等待连接或查看终端；不代表检测到真实 Wi-Fi 状态 | `connecting.png` |
| `thinking` | 思考：停顿、托腮或看资料 | `thinking.png` |
| `reading` | 阅读：打开书或文件夹 | `reading.png` |
| `searching` | 搜索：寻找、翻资料 | `searching.png` |
| `tool_use` | 工具调用：拿起工具或选中文件夹 | `tool-use.png` |
| `working` | 工作：专注处理事情 | `working.png` |
| `testing` | 检查：核对结果 | `testing.png` |
| `generating` | 生成：创作中的期待表情 | `generating.png` |
| `needs_input` | 等待用户：抬头询问 | `needs-input.png` |
| `ready` | 完成：开心但保持角色一致 | `ready.png` |
| `blocked` | 遇到问题：困惑，而不是缺腿或缺身体的半身图 | `blocked.png` |

每张都对照母版检查脸形、眼睛、发箍、尾巴、衣服与腿。道具遮挡是设计，身体缺失是缺陷，二者要区分。

拖动倒挂图是**额外的特殊姿势**，不属于这 12 个状态。路线 A 的设置页面暂时不能替换它，也不能替换程序内置的眨眼素材；完整替换角色需要路线 B 的第 7 步。

## 4. 做到真正透明，而不是看起来像透明

PNG 扩展名不保证透明。白底、浅蓝底、甚至棋盘格，都可能被画进图片本身。把 JPG 改名为 PNG 也不会得到透明通道。

### 4.1 先判断是否需要抠图

在支持图层的图像编辑器中打开原图，在下面放一层黑色，再换成深蓝色。若角色外面和发丝空隙已经显示下层颜色，保留原有 Alpha；**不要对已经干净的图重复运行抠图模型**。

8 位 Alpha 中：`0` 完全透明，`255` 完全不透明，中间值是柔和边缘。白色发箍本身可以是不透明白色；呆毛与发箍之间真正属于背景的空洞应当透明。

### 4.2 白底图：可选的免费本地动漫模型路线

本项目历史上使用过 `isnet-anime`。下面固定到 `rembg 2.0.81`，其文档要求 Python 3.11–3.13，并提供 CPU 模式。首次使用会下载模型；依赖和模型准备好后，本地 ONNX 推理不需要上传图片。[rembg 官方版本文档](https://github.com/danielgatis/rembg/blob/v2.0.81/README.md)

这是可选制作工具，不是桌宠的运行依赖。新建一个独立的 `sprite-lab` 文件夹，在其中放入 `input.png`，再执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install "rembg[cpu,cli]==2.0.81"
.\.venv\Scripts\rembg.exe i -m isnet-anime input.png candidate.png
```

`py -3.12` 需要已安装 Python 3.12；若找不到，先安装对应版本。始终显式指定 `-m isnet-anime`，不依赖默认模型；不要跳过模型校验或把下载失败理解成抠图已经完成。为每次候选图使用不同文件名，不覆盖原图。

模型生成的是**候选蒙版，不是验收证明**。它也可能吃掉白色发箍、星星、感叹号或细发丝。我们后续仍做了逐处修复，而不是模型一跑就宣布完美。

旧制作脚本使用项目私有的模型缓存路径，GitHub 精简源码不包含这些模型和旧环境；读者应自行安装，不要照抄作者电脑上的绝对路径。

### 4.3 精修：只改确认属于背景的地方

在编辑器中把原图放在底层、候选图放在上层，通过蒙版逐处检查：

1. 放大到 400% 左右，找到呆毛、发箍、裙摆与头发的真实描边。
2. 对确定是背景的内部空隙，在蒙版上局部隐藏；不要按“所有白色”一键删除。
3. 发箍被误删时，从未受损的原图恢复正确区域，不要把整个白色矩形贴回来。
4. 星星和感叹号单独检查。保留它们的透明轮廓，而不是恢复带背景的整块裁图。
5. 回到实际显示尺寸，看局部修复是否产生缺口或硬边。
6. 导出 RGBA PNG，保留原文件及可编辑蒙版。

颜色差异可以帮助找背景，但不能取代轮廓判断。高光和纸面可能颜色相近，真正的角色细节也可能与背景连在一起。

### 4.4 白边不一定只由蒙版造成

缩放会混合边缘像素。预乘 Alpha 能减少透明像素隐藏颜色对缩放的污染；Pillow 对应模式为 `RGBa`，导出前需转回常规 `RGBA`。[Pillow Alpha 模式说明](https://pillow.readthedocs.io/en/stable/handbook/concepts.html)

但这**不能自动消除已经烘焙进半透明边缘的白色底色**，更不能恢复原画缺失的描边。把 Alpha=0 的 RGB 清零也只处理完全透明像素。遇到白圈应检查蒙版、边缘颜色和缩放方式，而不是反复扩大删除范围。

## 5. 四种背景验收与画布对齐

### 四背景检查

复制角色图层四份，分别放在黑色 `#080808`、深蓝 `#102045`、灰色 `#888888` 和棋盘背景上。背景只用于预览，**最终导出的 PNG 要隐藏这些测试背景层**。

每个姿势都检查：

- 呆毛内部是否显示当前背景，而不是白色或固定浅蓝色。
- 白色发箍、袖口和裙边是否完整，深色描边有没有被吃掉。
- 长发与裙子之间、手与道具之间是否还有纸面残留。
- 短腿、袜子和鞋子是否完整；特效是否带着背景方块。
- 正常大小和 75% 大小下，是否出现明显亮边、锯齿或细线结块。

如果怀疑某个洞没抠干净，记录原图像素坐标并读取 Alpha。**角色外有透明像素，不等于内部所有空隙都正确；抽查几个点也不能替代整张图的检查。**

使用 [验收清单](CREATOR_CHECKLIST.md) 留下结果，不要把上一个版本的勾选继承给新图。

### 画布与尺寸：两条路线不同

**路线 A：**导入器接受 PNG/WebP，文件不超过 8 MiB，边长不超过 4096。它会自动裁取可见区域并归一到 384×384，再按当前桌宠大小显示；因此导入 1280px 图片不代表本机自定义图会保留全部 1280px 像素。保持人物完整，先用预览确认大小即可。

**路线 B：**当前默认素材采用 1280×1280 RGBA PNG，放在 `assets/whalepet-hd/`。同一套姿势应该保持相近的头部尺度与脚底位置，不能把每一张都无条件撑满画布。

可操作的对齐方法：

1. 打开本项目默认 `idle.png`，保留为参照层。
2. 在另一张 1280×1280 透明画布上放入自己的待机图，等比例缩放，匹配参照的身体高度；不要横向拉伸。
3. 建立头部中心线与脚底参考线。当前默认图用于测试的脚底位置约为 `y=1246`（从 0 开始的像素坐标）；这是本项目的布局约定，不是通用绘画标准。
4. 依次导入其他姿势，保持身体尺度一致。带高举特效的图片，要根据身体对齐，不要因特效变高而把整个人缩小。
5. 导出到独立候选目录，在程序中逐状态预览，验收后才替换正式文件。

`384×384 / y=374` 是旧素材及当前设置导入器的约定；`1280×1280 / y≈1246` 是当前默认高清素材约定。不要把旧的矩形抠图坐标直接套到高清图上。

## 6. 把自己的姿势接入桌宠

### 路线 A：不写代码

1. 右键小鲸鱼 →「小鲸的控制室」→ 姿势图片。
2. 为一个状态选择自己的透明 PNG/WebP。
3. 预览，检查轮廓、大小、腿和道具。
4. 不满意就恢复该姿势默认图，再回编辑器修正；不要不断修改唯一的原文件。
5. 逐个完成其余状态，切换到 75%、100%、150% 检查。

导入的副本和偏好存储在本机。修改待机图后，原角色专用的局部眨眼/摆尾效果不会套到新角色上，这是保护机制，不是导入失败。倒挂图仍是原版；想一起更换，继续路线 B。

### 路线 B：默认素材成为你的作品

先在原版程序的右键设置中关闭「待机微动作」，以免旧的眼睛与尾鳍坐标被用在新角色上。

1. 备份 `assets/whalepet-hd/`，把验收过的 12 张图复制到自己的源码副本中，保持第 3 步的文件名。
2. 完整退出并重启源码版，避免误看已经安装的旧版。
3. 若此前在设置中导入过自定义图片，逐项恢复默认图片，让程序重新显示你刚替换的默认素材。
4. 逐个预览所有状态。不要为了让图片出现而改状态键；程序保留 `.webp` 逻辑名称，但 `pet.js` 的 `asset()` 会把默认图片映射到高清 `.png`。
5. 自己的角色尚未校准眨眼时，发行版可将 `preferences.js` 的默认值改为 `idleLife: value.idleLife === true`。这样新安装默认关闭微动作；旧用户已保存的开关仍需在 UI 中关闭。功能未适配完成前，在说明中提示不要开启。

换角色并不需要重写 `main.js` 的拖动跟踪、透明点击穿透或状态优先级。

## 7. 添加倒挂、呼吸与眨眼

### 倒挂图是单独的绘画

完整翻转、衣服重力感、脸部朝向与尾巴结构需要设计，简单把站姿旋转 180° 不一定好看。

1. 制作一张通过短尾巴悬挂的完整角色图，抓取点上方留边；不包含鼠标手形、文字或背景。
2. 在四种背景审核后，替换源码副本中的 `assets/generated-transitions/tail-hang/pose.png`。当前原图是 1254×1254，最省事的方式是沿用该画布和尾巴位置。
3. 在 `pet.js` 中查看 `DRAG_TAIL_ANCHOR`、`FRAME_SCALES`；在 `style.css` 中查看拖动时 `.stage` 的变换原点。新图尾巴位置不同，必须一起校准绘画位置、CSS 旋转支点和原生鼠标锚点。
4. 当前角色容器是 300×342 CSS px，容器内尾巴锚点 `(150,110)`；固定透明画布是 560×560，容器偏移 `(130,170)`，因此窗口内支点是 `(280,280)`。这不是图像源像素坐标，不能直接在 1254px 图片上填同一个数值。
5. 先慢速拖动确认尾巴跟着鼠标，再尝试快速左右反向和连续松手。

当前惯性由 `drag-physics.js` 的时间积分、速度响应和阻尼产生，是为了可爱手感调整过的弹簧摆动，不是严格的刚体物理仿真。显示角度没有原先的 ±22° 限制，但仍保留数值稳定保护。

### 呼吸要连续，小尺寸要稳定

整身呼吸使用平滑往返，不能把多个各自减速的小片段随意拼接。85% 及以下会暂停持续整身浮动与尾鳍摆动，保留交互与允许的眨眼；这能减少小尺寸细线的闪烁。

不要为了让动作更明显而不断缩放整张精细图。先确认 75% 显示稳定，再增加动作幅度。

### 眨眼是进阶选做

当前 `idle-life.js` 只混合眼部局部区域，并对尾鳍做局部形变。这些区域、闭眼图对齐参数均针对原角色，不适合直接套用另一张脸。

制作自己的闭眼图 → 对齐到待机图 → 校准眼部遮罩和尾鳍区域 → 测试开关与 GPU 失败回退。完成以前保持关闭；一个稳定完整的静态角色，比偶尔眼睛错位的动画更好。

**不要为了倒挂或换姿势，在每次拖动时反复扩大、缩小透明窗口。**现有固定画布与释放坐标计算已经解决过残影和累计偏移，应保留。

## 8. 让角色反映 AI 状态

先区分「选一张姿势」和「真的收到工作事件」。改标签不会让桌宠自动读懂其他软件。

本项目提供：本机 Codex 事件跟随，以及 ChatGPT、DeepSeek、自定义 AI 三个本机状态通道。普通 ChatGPT 网页和普通 ChatGPT 桌面端不在当前自动跟随范围内。具体以项目的 [接入说明](../PROVIDER_INTEGRATION.md) 为准。

先用自定义通道做简单测试：

1. 打开小鲸鱼控制室的 AI 接入页面，选择「自定义 AI」。
2. 在源码根目录执行：

```powershell
node set-whalepet-state.js --provider custom thinking "正在思考"
node get-whalepet-status.js
node set-whalepet-state.js --provider custom ready "完成啦！"
```

两次状态命令之间停一下，观察姿势。收到 ACK 只说明桥接收到消息；检查诊断中的 `renderedState`，并亲眼确认姿势是否改变。

3. 手动测试成功后，再由自己的 AI 程序在事件发生时发送：开始处理 → `thinking`，调用工具 → `tool_use`，完成 → `ready`，异常 → `blocked`，需要用户 → `needs_input`。
4. 有真实连接事件才发送 `connecting`；不要把它当作已经测量 Wi-Fi 的证据。

控制室提供 Python/JSON 示例。默认桥接地址是 `127.0.0.1:43815`，只用于本机；不要把它开放到公网，也不要把 API 密钥塞进状态消息或分享包。没有事件接口的软件，仍需要自己编写适配器。

先照 [验收清单](CREATOR_CHECKLIST.md) 手动检查，再运行源码测试。以下命令针对 GitHub 当前源码：

每条命令成功后再继续。图形测试会临时打开测试实例；不要在运行期间人工拖动这些测试窗口。`work/` 保存输出，不属于分享素材。

部分图像测试包含原版的尺寸、透明采样点、脚底或抓取坐标。换角色后应依据自己的母版重新标注对应真值，而不是为了消除红字而删除断言。未实现自有眨眼时，其专项测试不能宣称通过，应记作未适用/待实现，并保持该功能关闭。

原版曾通过 300 次快速拖放检查，但这不是新角色自动继承的成绩。请记录自己的测试日期、显示缩放、程序大小和结果。

常见现象与排查方向：

| 现象 | 先检查什么 |
| --- | --- |
| 发箍破洞，但白底还在 | 是否全局删除了白色；回原图恢复蒙版，不要继续侵蚀边缘 |
| 图片换了却看不到 | 是否启动了另一个安装目录、存在自定义覆盖、未重启 |
| 切姿势忽大忽小 | 身体尺度、脚底基线，是否按特效的最高点缩放了整个人 |
| 75% 时细线闪烁 | 小尺寸稳定模式、整身亚像素运动、显示缩放 |
| 甩动时尾巴脱离鼠标 | 源图片位置、CSS 原点与原生锚点是否对应 |
| 松手逐次偏到右下 | 是否保留原按下坐标和固定画布，而不是按倒挂尾巴位置恢复 |
| 状态桥说收到，但姿势不对 | 当前 provider、自动跟随覆盖、`renderedState` 和排队切换 |

## 10. 打包，让朋友看到你的角色

**不要压缩整个开发文件夹。**模型、node_modules 开发树、原图、运行缓存、聊天日志和备份都不需要交给朋友。

1. 确认路线 B 中 12 张默认图和倒挂图已替换；自定义导入偏好不会随包导出。
2. 用自己的图标替换 `assets/whalepet-v015/WhalePet.ico`，必须是真正的 ICO 文件，不是改扩展名。小尺寸下清楚比堆细节更重要。
3. 更新 `docs/FRIENDS-README.txt`、素材说明及自己的版本说明。保留实际使用的第三方许可，不宣称拥有他人的角色图。
4. 若要作为另一个独立产品与原版同时存在，不要只改桌面名字：安装器中的应用目录、程序的单实例锁/用户数据标识以及状态桥端口都需一起设计。当前脚本仍按 WhalePet 安装，可能覆盖已有 WhalePet；应明确告诉朋友先退出原版。
5. 安装 PowerShell 7，确认 Windows 的 .NET Framework C# 编译器可用，执行：

```powershell
pwsh -File tools/build-friends.ps1 -ReleaseName WhalePet-Friends-20260930
```

在未来日期制作时可换成新的日期。脚本只接受指定格式，并拒绝覆盖同名文件。它仅打包明确列出的程序和默认素材，因此不能靠把图片随手放进任意文件夹来发布。

6. 检查根目录生成的 ZIP 与其 SHA-256。把 ZIP 解压到一个新目录，从这个新目录试装和启动，而不只是测试原开发目录。
7. 检查桌面图标、全部姿势、AI 接入说明、75% 显示、拖放、退出；有条件时在另一台 Windows x64 电脑再试一次。
8. 给朋友发送 ZIP 或发布到你自己的 Releases。告诉对方先完整解压、再运行安装器；不要让对方关闭安全保护。

当前构建脚本提供的是程序安装包，不是个性化配置导出器。只想分享制作方法时，直接分享本指南和验收清单即可。

新增音乐图 `assets/whalepet-music/dancing-v1.png` 也应换成你自己角色的透明图，并检查点击区和舞步。音乐只导入个人运行目录，不会自动打入 ZIP；默认关闭自动唱歌，分享前验证安静模式。多任务与刷新行为见 [使用指南](USER_GUIDE.md)。

## 最后：我们希望传下来的制作习惯

每张图都回到同一母版，每个修复都有可对照的原图，每个动作都在真正的小尺寸上试过。学别人的工程经验，不拿别人的角色替代自己的设计。

小鲸鱼不是一次生成就完成的：她是在「这里的白色是背景」「腿可以短，但要看得到」「拎住短尾巴，整只倒挂」这些具体反馈里，一点一点变得可爱的。

做好一张，验证一张，再往前走。你的桌面伙伴也会慢慢长出自己的样子 AuA。
