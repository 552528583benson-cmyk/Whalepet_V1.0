# WhalePet 本地动漫抠图与四背景验证指南

> 历史记录提示（2026-09-25）：本文记录旧素材阶段的抠图流程和当时的测试，不是当前高清版本的完整制作教程。新用户请从 [从零制作你的小鲸鱼桌宠](MAKE_YOUR_OWN_WHALEPET.md) 开始；不要把旧 384px 修复坐标用于高清图，也不要把本文的勾选结果视为新素材已通过验收。同名 Word 文件保留原历史版本。

> 目标：保留已经认可的角色设计、姿势和动作，只修复透明背景、发箍、呆毛、腿部与离散特效，不重新绘制角色。

## 1. 最终采用的路线

可以，这次我会按你说的回到以前那条路线：不用重新画角色，而是用免费的本地动漫抠图模型重新处理新姿势，再在黑、深蓝、灰、棋盘四种背景上逐张验证。因为这是图像编辑任务，我会遵循图像处理技能的检查流程，但尊重你的要求，只使用本地模型。

项目中已经保存了之前成功使用的本地模型：`work/models/rembg/models/isnet-anime/isnet-anime.onnx`。它不需要再次下载，不联网，也不收费。处理从最初的动作设计大图重新裁切，并首先写入独立验证目录，不覆盖桌宠当前使用的素材。只有通过像素检查的候选图才会进入成品。

## 2. 为什么以前会反复出现白底和发箍损坏

| 现象 | 根因 | 对应处理 |
| --- | --- | --- |
| 呆毛与发箍之间仍是白色 | 这块背景被蓝色呆毛与深色轮廓包围，普通“从外向内”的清理无法到达 | 让 `ISNet Anime` 直接预测角色 Alpha，而不是只做白色阈值删除 |
| 白色发箍缺块 | 发箍本身接近白色，普通白底删除会把真实衣物一起删掉 | 使用动漫人物分割模型，并在黑色背景上检查每片发箍轮廓 |
| 深色背景出现浅色毛边 | 缩放时直接插值 RGBA，会把透明像素背后的白色 RGB 混入边缘 | 使用预乘 Alpha 缩放，并把完全透明像素的 RGB 归零 |
| 感叹号或星星消失 | 分割模型倾向只保留人物主体，会忽略与人物分离的小特效 | 本体采用模型 Alpha；黄色/橙色特效用受限颜色蒙版单独恢复 |
| 动作突然变高、变矮或没有腿 | 每张裁切范围和基线不统一，或误用了半身姿势 | 统一为 `384×384` 画布、`y=374` 脚底基线，并检查短腿与鞋子 |

## 3. 完整处理流程

1. **回到原始动作大图**：从 `assets/design-source/movement-sheet.png` 按提取报告重新裁出所需姿势，避免在已经受损的透明图上继续修补。
2. **增加纸张边距**：在裁图四周补上接近原页面的 `RGB(253,253,252)` 背景，使模型更容易区分人物与纸面。
3. **离线运行模型**：使用本地 `isnet-anime.onnx` 和本地 `rembg` 运行环境生成 RGBA 图，不访问网络。
4. **预乘 Alpha 归一化**：先裁到 Alpha 包围盒，再用预乘 Alpha 的 Lanczos 缩放放入 `384×384` 透明画布。
5. **统一身体尺度与脚底**：标准目标高度为 `319 px`，脚底落在 `y=374`，避免状态切换时突然变高或变矮。
6. **恢复原创特效**：只从已认可素材的限定区域提取黄色/橙色像素，恢复调用工具的感叹号和生成内容的星星；不复制整块背景。
7. **清理不可见颜色**：Alpha 为 0 的像素 RGB 统一为 0；保存为无损 WebP 时使用 `exact=True`，避免 Chromium 缩放暴露隐藏白边。
8. **独立验证后再接入**：候选图先保存在 `work/operation-isnet-validation/`，通过检查后才复制到正式资源目录。

## 4. 四背景逐张验收

每张姿势必须同时在以下背景通过：

- **黑色**：最容易发现发箍外围、头发边缘和裙边的白色残留。
- **深蓝色**：接近常见桌面与应用背景，可检查蓝发边缘是否自然。
- **灰色**：能同时暴露过亮白边和过深黑边。
- **棋盘格**：确认图片拥有真实 Alpha，而不是把棋盘格或浅蓝背景烘焙进图片。

重点放大检查两个区域：

- 头部：呆毛内部应显示当前测试背景，白色发箍的粉色阴影和深色外轮廓必须完整。
- 下半身：裙边旁的头发不得夹带纸面；短腿、袜子和鞋子必须存在，并落在统一基线。

## 5. 进入成品前的安全措施

- 当前运行素材先备份到带日期的目录，修复失败时可以立刻回滚。
- 模型生成结果、混合结果和正式成品分开存放，避免误覆盖。
- 使用版本化的素材修订号，让 Electron/Chromium 不会继续显示缓存旧图。
- 重新生成素材后运行透明度、发箍、转场、拖动和状态桥接测试。
- 安装版与分享版通过 SHA-256 核对，确保复制后的文件与工作区一致。
